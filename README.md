# 台大校園路徑規劃視覺化系統 (NTU Campus Pathfinding Visualization)

這是我們開發的台大校園路徑規劃視覺化系統，我們將台大校園地理特徵抽象化為圖論結構，並透過視覺化動畫即時演示利用 **Dijkstra** 與 **A*演算法** 尋路的運作流程。

## 一、 使用者操作指南


**步驟一：設定導航端點**
   - 在控制面板的下拉選單中分別選擇 **「起點」**（例如：總圖書館）與 **「終點」**（例如：校門口）。
   - 或者，直接在地圖上點擊代表地標的節點。

**步驟二：選擇巡路演算法**
   - 點擊介面上的演算法切換按鈕（可選擇 `Dijkstra` 或 `A*`）。

**步驟三：控制演示節奏**
   - 點擊 **「自動演示」**：演算法將以固定速度自動向外搜尋。
   - 點擊 **「手動演示」**：可進入手動除錯模式，一格一格觀察指標與節點狀態的轉變。

**步驟四：檢視搜尋結果**
   - 搜尋完成後，畫面上會以 **綠色折線** 標示出最終路徑，下方的狀態儀表板將同步顯示「路徑總長度」與「已拜訪節點總數」。

---

## 二、 演算法運作原理與邏輯 (DSA Logic)

本系統核心實作了兩種導航巡路演算法，其邏輯運作機制如下：

### 1. Dijkstra 最短路徑演算法
   - **核心邏輯：** 用相鄰節點真實距離當權重，並維護一個累積距離表。每次皆從 Priority Queue 中取出目前累積距離 $g(n)$ 最短的節點進行鬆弛操作。它是一種盲目的貪婪搜尋，確保能找到全局最優解。

   - **時間複雜度：** $O(V \log V + E)$
   - **在本專案的視覺化表現：** 搜尋邊界會從起點開始，像同心圓或波紋一樣「盲目地」向四周所有方向擴散，直到觸及終點為止。節點外框會即時更新當前的累積權重。



### 2. A* 啟發式搜尋演算法 (A-Star Algorithm)

- **核心邏輯：** 在 Dijkstra 的基礎上引入了**啟發式函數 (Heuristic Function) $h(n)$**（節點到終點的估計距離）。其總評估函數為 $f(n) = g(n) + h(n)$，其中 $g(n)$ 為起點到當前點的累積距離，$h(n)$ 為當前點到終點的估計距離。每次優先擴展 $f(n)$ 值最小的節點。

- **時間複雜度：** 最壞情況為 $O(V \log V + E)$，但在良好啟發式引導下，實際搜尋時間與空間複雜度遠小於 Dijkstra。
- **視覺化表現：** 搜尋邊界展現出強烈的 **「方向性」**。演算法會明顯地優先「朝著終點的方向」延伸，大幅減少不必要的節點拜訪，直觀呈現啟發式引導的威力。

## 三、 執行範例與分析
以下為系統在特定起訖點下的搜尋表現與數據對比：

### 範例：從【校門口】導航至【德田館】
| 評估指標 \ 演算法 | Dijkstra (最短路徑) | A*(啟發式) |
| :--- | :--- | :--- |
| **最終路徑總長度** | 1117.5米 | 1117.5 米 |
| **演算法拜訪節點數** | 5201 個 | 1931 個 |
| **搜尋結果結論** | 找出最少節點數路徑 | 能用更少的拜訪節點數抵達終點 |

## 四、 EXTRA BONUS
除了地圖導航外，我們還弄了一個小專案，可以更清楚的演示 **Dijkstra** 是如何運行的，從畫面上方可以點擊切換。

1. **自由蓋地圖：** 在編輯介面點擊 **拖曳節點**、**新增房間**、**新增通道**、**設定權重** 。
2. **啟動挑戰：** 設定好起點與終點後，點擊開始搜尋。
3. **勝利通關：** 手動點擊 **下一步**，觀看 Dijkstra 的運行過程。如果有路徑可以到終點，則會顯示攻擊動畫，否則會是 **找不到目標** 的提示。

## Development
### First time

- To start development, run this command at the root folder of this project.
```bash
npm install
```

### How to use

- Run website in dev mode
```bash
npm run dev
```

- Preview website
```bash
npm run preview
```

- Build the website
```bash
npm run build
```

### Where to put files

- `/src`
To put .js, .css, etc.

- `/src/assets/`
To put pictures, static data, etc.

- `/public`
To put icons, etc.
